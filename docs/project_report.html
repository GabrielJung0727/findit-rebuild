01

프로젝트 개요 및 배경

PROJECT OVERVIEW

FindIt: The Battle 는 2012~2014 년 KT olleh / SKT T-Store / Samsung Galaxy Store / Google Play 에서 서비스되었던 한국형 멀티플레이 "다른 그림 찾기" 모바일 게임이다. 원본 백엔드 서버 14.63.220.39 가 서비스 종료되어 클라이언트 APK 만 남아있었으며, 본 프로젝트는 디컴파일된 Java 코드로부터 게임 로직을 복원하고 신규 서버 인프라를 구축하여 재출시 가능 상태로 만드는 것을 목표로 한다.

1.1 프로젝트 목표

  • 원본 게임 로직 보존 — 디컴파일된 Java 21,678 줄을 Gradle 빌드 가능한 형태로 복원 (jadx 아티팩트 수정)
  • 백엔드 재구축 — REST API 14개 + TCP 멀티플레이 소켓 + 어드민 대시보드
  • 2013 최종 밸런스 적용 — 권아영 기획서 (2012-05 ~ 2013-07) 의 모든 수치 반영
  • 현대화 — HTTPS / 영수증 서버 검증 / 보석(Gem) 화폐 / 보안 강화
  • 저비용 배포 — GCP Always Free 티어 + $300 크레딧 활용

02

원본 게임 분석

FIND THE DIFFERENCE BATTLE — REVERSE ENGINEERING

원본 APK 는 jadx 디컴파일 후 Gradle 빌드 가능하도록 재구성되어 있다. 게임은 가로 모드 1:1 멀티플레이 다른 그림 찾기로, 한 이미지에 7개의 차이를 두고 5개를 먼저 찾는 사람이 승리하는 40초 배틀 게임이다.

2.1 게임 흐름 — 6 화면 모드

[0] OPENING ──► [1] MAIN MENU ──► [2] WAITING ROOM ──► [3] BATTLE ROOM ──► [4] GAME PLAY ──► [5] RESULT │ ├──► CHARACTER (스킬/아이템/샵) ├──► RANKING (친구/전체) ├──► OPTION (사운드/자동로그인) └──► NOTICE (공지사항 — WebView)

2.2 핵심 게임플레이 규칙

전투 규칙

  • 제한 시간 40 초
  • 이미지당 7개 차이 중 선착 5개 찾기
  • 오답 터치: 화면 200ms 진동 + 디밍
  • 승자 = 5개 선착 또는 시간 만료 시 더 많이 찾은 자

점수 공식 (2013 기획)

  • 승자 = 찾은수 × 50 + 승리 보너스 100
  • 패자 = 찾은수 × 50
  • 콤보 보너스: 1·2·3·4 → +100·200·400·700 점
  • 아이템 시간 보너스: 1·2·4·7 초

2.3 디컴파일 아티팩트 수정 내역

jadx 출력은 그대로 컴파일되지 않아 다음을 손봤다 (총 ≈ 80건).

03

시스템 아키텍처

SYSTEM ARCHITECTURE

클라이언트는 원본 Android APK 그대로 유지하면서 서버 주소만 교체했다. 서버는 Node.js + Express 단일 프로세스가 HTTP REST 와 TCP 소켓을 동시에 서빙한다. 인메모리 매칭은 DAU 1,000 이하에서 충분하며, 그 이상에서는 Redis 분리를 권장한다.

3.2 통신 프로토콜

HTTP REST

  • GET 위주 (원본 클라 호환)
  • application/x-www-form-urlencoded
  • 응답: JSON, result 필드 (000 ~ 999)
  • userId = 이메일 (PK)

TCP Socket

  • 4자리 zero-pad 길이 + |code|payload
  • 코드 100~107 (UserList/Room/Ready/Game/Invite)
  • UTF-8 byte stream
  • 오프라인 타겟 → FCM 자동 fallback

4.3 게임 루프 — 60 FPS 목표

GameThread 가 16ms 슬립으로 Canvas 를 다시 그리며, mDelay 를 동적 조정해 프레임을 맞춘다. AI 시간 공식 7 - level × 0.03 초도 60 FPS 단위로 환산되어 적용된다.

// GameView.java getAIFindTime()
double seconds = 7.0 - (level * 0.03);
int frames = (int)(seconds * 60.0);
int variance = (int)(frames * 0.15);
return randomNumber(frames - variance, frames + variance);

서버 구조 (Node.js + Express)

BACKEND — NODE 18+ / EXPRESS 4 / MYSQL 8

원본 서버는 Spring 추정이나 정확한 스택은 알 수 없다. 신규 서버는 Cloud Run 친화적 컨테이너화를 위해 Node.js + Express 로 작성되었다. HTTP 와 TCP 가 단일 프로세스에서 공존하며, 코드 줄 수는 2,500 미만으로 가볍다.

14.3 imageCut 검증 (스테이지 등록 시)

틀린그림 이미지 등록 시 7개 좌표가 이미지 경계를 벗어나는지 자동 검증.

function validateImageCut(cut, imgW, imgH) {
  if (!Array.isArray(cut)) return 'image_cut must be array';
  if (cut.length !== 7) return `length must be 7 (got ${cut.length})`;
  for (let i = 0; i < 7; i++) {
    const {x, y, w, h} = cut[i];
    if (![x,y,w,h].every(v => Number.isInteger(v) && v >= 0)) return `[${i}] invalid`;
    if (w === 0 || h === 0) return `[${i}] w/h must be positive`;
    if (x + w > imgW || y + h > imgH) return `[${i}] exceeds image ${imgW}x${imgH}`;
  }
  return null;
}

    body: new URLSearchParams({ secret: process.env.RECAPTCHA_SECRET, response: token, remoteip: ip }),
  });
  const data = await r.json();
  if (data.success && data.score < MIN_SCORE) return { success: false, reason: 'score_too_low' };
  return data;
}

RECAPTCHA_SECRET 미설정 시 no-op — 개발/마이그레이션 환경 호환.
